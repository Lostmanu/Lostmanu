# Hi, I'm Manuel

I'm an electronics and control engineer in Spain. I read AI evaluation suites next to the papers they
implement, and when a scorer, a sample id or a declared count doesn't match the benchmark, I measure the gap
with the real code and send the fix.

## What I'm working on

- Fixes to open-source evaluation suites. Two merged in the UK AI Security Institute's
  [inspect_evals](https://github.com/UKGovernmentBEIS/inspect_evals):
  [`worldsense`](https://github.com/UKGovernmentBEIS/inspect_evals/pull/2507) had never evaluated a single
  `FALSE` or `IMPOSSIBLE` answer, and [`apps`](https://github.com/UKGovernmentBEIS/inspect_evals/pull/2489)
  declared 5,000 samples and loaded 3,000.
- Open: two more in inspect_evals ([#2490](https://github.com/UKGovernmentBEIS/inspect_evals/pull/2490),
  [#2491](https://github.com/UKGovernmentBEIS/inspect_evals/pull/2491)), one in EleutherAI's
  [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness/pull/4215) and one in ModelScope's
  [evalscope](https://github.com/modelscope/evalscope/pull/1773).

## How I work

I preregister what counts as success before the data exists, and I build controls that have to prove they
bite. I work with AI coding agents, and I keep a public record of every claim that turned out to be false,
theirs and mine.
